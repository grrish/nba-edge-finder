# Slice 1.1 — Prop scoring & pipeline verification

## Objective

Verify `EdgeEngine._score_prop_edge()` and `EdgeEngine.find_prop_edges()` in
`backend/services/edge_engine.py` satisfy every scoring/pipeline clause of
`prds/prop-edge-pipeline/prd.md`'s definition of done. **Research first,
confirm what's already correct, and fix only genuine gaps** — this code is
not a stub in this branch's current state; treat any temptation to rewrite
wholesale as a signal to re-read the code more carefully, not as license to
replace it. See `pattern-dont-silently-fix-scaffolds` in the Expert's
long-term memory.

## User story

As the developer, when I call `EdgeEngine._score_prop_edge(prop)` on a
single OddsService prop dict, I get back an `EdgeScore` computed the same
way `_score_game_edge` computes one — so prop scoring is trustworthy on its
own, before the full pipeline is exercised.

## What to verify (against the actual file, not this description)

**`_score_prop_edge(prop: dict) -> Optional[EdgeScore]`**

- Builds one `MarketPrice` per prop from `prop["bookmaker"]` (source),
  `prop["over_prob"]` (implied_probability), `prop["over_american"]`
  (odds_american).
- Sets `event_type="prop"` on the returned `EdgeScore`.
- Uses `model_prob: float = 0.5` — literal, unconditional. This line must
  read exactly `model_prob: float = 0.5` (the PRD test's static guard greps
  for `"model_prob: float = 0.5"` in `edge_engine.py` verbatim — do not
  reformat, rename, or wrap it).
- Computes `best_edge = model_prob - over_prob`.
- Computes `kelly_fraction = max(0.0, edge_value / (1 - over_prob))` when
  `over_prob < 1`, else `0.0` — mirrors `_score_game_edge`'s Kelly formula
  exactly (same shape, different implied-probability source).
- Sets `is_positive_ev = edge_value >= _MIN_EDGE_THRESHOLD`.
- `best_source` is the prop's `bookmaker`.
- Wrapped in try/except, returning `None` (and logging) on any missing key
  or malformed input — same defensive shape as `_score_game_edge`.

**DO ✅ — score against the real prop dict shape**
```python
losing_prop = {
    "game_id": "g1", "player_name": "Losing Player", "stat_type": "points",
    "line": 20.5, "over_american": -110, "under_american": -110,
    "over_prob": 0.5238, "under_prob": 0.5238, "bookmaker": "draftkings",
}
# _score_prop_edge(losing_prop).is_positive_ev is False:
# best_edge = 0.5 - 0.5238 = -0.0238 < _MIN_EDGE_THRESHOLD (0.02)
```

**DON'T ❌ — reach for `NBAPredictor` because "the model should inform this"**
```python
# NEVER do this in _score_prop_edge or find_prop_edges:
model_prob = self._predictor.predict_prop_outcome(...)
```
The PRD test statically greps `edge_engine.py` for any co-occurrence of
`_score_prop_edge` and `NBAPredictor` and fails the build if found. The
`model_prob = 0.5` placeholder is intentional and deferred — see
`decision-predictor-ml-integration`.

**`find_prop_edges(player_id: Optional[str] = None) -> List[EdgeScore]`**

- Fetches `self._odds.get_nba_game_lines(sport=_WNBA_SPORT)` — the real
  method name (not `find_game_edges`'s broken `get_game_odds()`). Wrapped in
  try/except; on failure, log and return `[]` (matches `find_game_edges`'s
  shape).
- Per game, fetches
  `self._odds.get_nba_player_props(game["game_id"], sport=_WNBA_SPORT)` —
  also try/except per fetch, `continue` to the next game on failure (not a
  full-pipeline abort — a single bad game shouldn't kill the whole scan).
- Applies the `player_id` filter case-insensitively against
  `prop.get("player_name", "")` **before** scoring (skip scoring work for
  props that don't match).
- Scores every remaining prop via `_score_prop_edge`, keeps only
  `is_positive_ev` results.
- `edges.sort(key=lambda e: e.best_edge, reverse=True)` before returning.

## Success Criteria

- `backend/services/edge_engine.py` contains `model_prob: float = 0.5`
  verbatim, and no code path lets `_score_prop_edge` or `find_prop_edges`
  call into `NBAPredictor`.
- `_score_prop_edge` returns the right `EdgeScore` (event_type, best_edge,
  best_source, is_positive_ev) for both a synthetic losing prop and a
  synthetic winning prop, matching the math above.
- `find_prop_edges` fetches via `get_nba_game_lines`/`get_nba_player_props`
  (not the nonexistent `get_game_odds`/`decimal_to_implied_prob`), filters
  to positive-EV only, sorts descending by `best_edge`, and the `player_id`
  filter narrows to case-insensitive `player_name` matches.
- The first two check blocks of `./prds/prop-edge-pipeline/run-prd-test.sh`
  (the static ML-placeholder guard, and the fixture-data scoring/pipeline
  check) pass. Run the script and confirm — don't infer from reading code
